# wujincheng



### 首个目标

#### 游戏玩法
对标游戏：90年代坦克大战（简化）
2个玩家在一个固定地图，初始状态一个在上方，一个在下方，初始3滴血  
玩家操控一辆坦克，可以进行上下左右攻击5种操作  
移动操作限制0.1s(可以调整)，每次移动跳跃式移动（直接赋值），移动的条件是目标网格是空格  
射击的操作也要时间限制。子弹的射击方向是玩家的朝向（最后一次移动的目标），子弹移动也是跳跃式（直接赋值）。目标是空格，移动；如果移动目标是玩家，则玩家死亡，子弹销毁；目标是可破坏墙，则该墙变为空格，子弹销毁；目标是墙，子弹销毁。 
初始地图分为3种 空格/不可破坏墙/可破坏墙
如果某一玩家死亡，游戏结束

### 7.31 代码框架：
消息协议 ServerMessage ClientMessage  
里边除了房间消息，其余的都是帧消息  
服务器帧消息：帧数；各个玩家输入；各个玩家选取的道具

### 由于是简单的帧同步，所以重心放在客户端 
#### 客户端处理消息：
获取到消息之后分类，但是不再使用事件系统，因为先后顺序无法控制也不够直观
收到什么消息就在哪一个条目中处理
#### 客户端处理游戏开始消息
首先levelManager来加载关卡，MapManager加载地图，EnemyManager来生成敌人，PlayerManager生成玩家，CamController控制相机大小适配地图，RoomManager关闭UI
#### 客户端处理帧消息
这个是重点，我将游戏中所有的Update()都改成了UpdateFrame(),以便处理  
首先是交给GameStateMnager处理输入和道具获取，这也是这游戏和原版不同的地方，我设计了一套肉鸽方案，当玩家击杀特殊敌人的时候，击杀的玩家会弹出一个三选一的界面，这个界面就是我所说的道具（食物），里边有一次性操作，分为3个等级，一般升级到最后一个级别的时候都是持久化效果，这样既兼顾了原版的道具，也实现了肉鸽游戏的叠叠乐的效果，让玩家希望得到道具。再说代码层面，道具分为了UItimerEntity,因为他们一般是进过一段时间之后产生效果，玩家能够观察到效果，另外一类是MapEntity,代表他们是会生成在地图中的道具，而不仅仅是计时之后产生效果。处理完这些，然后处理子弹的移动，坦克的移动，地图相关道具（其实目前只有一个，保护基地），敌人ai行动，玩家复活时间，实体推进

### 玩法上
结合1900坦克大战和吸血鬼幸存者，待完善的地方，一般的肉鸽后期需要大量的敌人，而且敌人也要有成长或者特殊能力，但是当前这个tank ai已经完成了，会发射子弹，难度已经完全超越最原始肉鸽游戏，但是这些坦克ai非常随机，当然这是继承了坦克大战的ai,就是无脑发射，然后碰到障碍就会随机转向。然后还有一个机制就是可以选择初始玩家，其实这个只是说玩家自带一个道具，类似吸鬼游戏的选择初始角色。此外，还有一个问题，就是我这个游戏没有使用物理引擎，全是格子交互
